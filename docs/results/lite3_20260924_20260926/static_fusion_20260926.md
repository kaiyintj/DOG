- 使用已有安装位置的候选雷达到相机外参；`projection_calibration_verified=false`。调试投影允许运行，正式几何标定和导航目标尚未验收。
- 隔离的 `chair` 查询被接受并找到候选，随后因标定未验证而拒绝发布目标与导航目标。Goal Bridge 未启动，测试窗口内 `/cmd_vel` 发布者最大值为零，`MOTION_READY=NO`。
- 日志记录一次缺少时间对齐 IMU 样本，运动可靠度降为 0.2；约 0.604 秒后恢复。这段静止功能检查不能证明运动时间同步合格。

- 前次两分钟运行因观察器把 best-effort 概率流误设为 reliable 而未能完整验收；本轮已修正观察器 QoS。前次原始失败记录保留在相邻目录 `lite3_live_indoor_fusion_20260926T202301`。

## 9 月 26 日追加排查：低电量趴下、IMU 对齐与退出异常

用户补充机器狗曾因低电量趴下，确切时间与当前姿态尚未提供。本轮原始通过状态证明数据输出与门禁检查通过；“全程静止”这一现场前提现在不能确认。如果趴下发生在观测窗口内，身体相对环境的位姿已经改变，本轮采用固定 `rslidar` 坐标的地图不能作为静止几何精度证据。传感器在身体上一起运动不等同于安装外参被改动。

历史 IMU 告警时刻为北京时间 20:24:20、20:24:21、20:25:02 和 20:32:16。代码在雷达时间戳前后 0.15 秒找不到有效 IMU 样本时才报 `no time-aligned IMU sample`；身体运动幅度较大走的是运动可靠度计算路径，不直接产生这个告警。低电量可能伴随其他设备或数据流变化，但原始试验没有同步记录电池/姿态事件和完整 IMU 接收时序，不能据此确认因果。

追加了 8 秒轻量传感器观测和 45 秒模型/融合负载观测，不新增 Bag 或图片，结果记录在 `diagnostic_timing.json`：负载窗口 IMU 8998 条（199.726 Hz）、图像 674 条（14.961 Hz）、雷达 450 条（9.989 Hz）。IMU Header 最大间隔 12.513 ms，接收最大间隔 82.250 ms，角速度模最大 0.02624 rad/s；没有再次出现 IMU 对齐失败。年龄统计包含传输、调度与两端时钟差，不是硬件时间同步精度。语义输出仍有间歇，不能用平均频率证明严格实时性。

退出异常得到真实调用边界复现：20:49:13.366781 请求 SIGINT；20:49:13.367221，ROS context 已为关闭状态，executor 从 `/timefix/lidar` 执行 `take_message(CustomMsg)` 时产生完整的转换 RuntimeError，融合节点退出 1。见 `diagnostic_ga.log`。这次异常发生在主动停止过程中，不是机器狗身体运动引起的融合崩溃。

源码在 `ga_bsvm_node.main()` 中仅接受“context 已关闭 + 本次实测完整转换错误消息”的组合。context 有效时该异常仍抛出，其他 RuntimeError 仍保留。相关 shutdown 定向测试 8 项通过，语法与 `git diff --check` 通过。已有 symlink-install 指向该源码，因此无需为这项 Python 修改重建第三方组件。

修正后再用真实输入观测 15 秒：同一退出错误在关闭 context 后再次实际触发，随后进入正常退出，模型与融合节点均退出 0。见 `shutdown_fixed_ga.log`、`shutdown_fixed_timing.json`。测试进程均停止，观测中 `/cmd_vel` 发布者为零；未发送运动命令，未修改标定或导航门禁。两次追加排查只增加约 53 KiB 的结果与日志。IMU 历史失败未在本轮复现，不能标为已修复。
